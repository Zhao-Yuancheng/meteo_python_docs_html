第 6 章术语：气象数据计算 NumPy#

配套 气象数据计算 NumPy 正文使用。每个词条 = 一句话定义 + 生活类比（气象优先） + 代码示例 + 易混淆点。本章术语围绕"多维数组、向量化、缺测处理"展开，代码统一用 3 站 × 5 天（或 5 个站点）的气温矩阵与标准化来演示。

参见

配套正文：气象数据计算 NumPy　·　配套练习：第 6 章练习《NumPy 基础》将在随后交付后上线（链接到时补全）。

数组（ndarray）#

NumPy 的核心数据对象「N 维数组」，是一块元素数据类型完全一致、按规则排列的连续内存格子。

生活类比 —— 一张排好的气象观测记录表。普通 Python 列表像一列随手贴的便签（什么都能夹）；ndarray 像一张排好的表格——每一格都填同一种量，比如整张表全部是某时段各站的气温，而不是「一格温度、一格站名」。

import numpy as np
temp = np.array([16.2, 13.5, 14.0, 18.6, 12.8])   # 5 个站点的即时气温（℃）
print(temp.dtype)      # float64，全是浮点数

易混淆点 —— array/ndarray 和 Python 列表很容易被混淆，但行为差别巨大：列表 + 是拼接，数组 + 是逐元素相加；列表可以混类型，数组不行。切片行为也不同（数组切出来是视图，见「形状」词条）。

维度 / 轴（dimension / axis）#

维度是数组的「层数」（1 维像一条线、2 维像一张表、3 维像一摞板），而轴（axis）是数组的每一条「方向线」。

生活类比 —— 你在敦煌看地图。一维像东西向的一条公路（只有经度在动）；二维像一张平面地形图——axis=0 好比南北方向，axis=1 好比东西方向；三维就像把这个地图叠成一层压一层的高程压片（多了竖直方向）。

mat = np.array([            # 3 天 × 5 站
    [16.2, 13.5, 14.0, 18.6, 12.8],
    [17.0, 14.2, 14.8, 19.1, 13.5],
    [15.8, 12.9, 13.4, 17.9, 12.1],
])
print(mat.ndim)            # 2（二维：行、列两个轴）
print(mat.mean(axis=0))    # axis=0：消掉行→每站的日均温（5 个数）
print(mat.mean(axis=1))    # axis=1：消掉列→每天的区域平均（3 个数）

易混淆点 —— axis=0 到底「消掉哪一维」最常见。判别口诀：axis=0 消掉行，输出每一列；axis=1 消掉列，输出每一行。二维矩阵的轴方向会随 shape（行/列）而变，务必先 print(shape) 认清楚，这也是气象高频出错点。

形状（shape）#

shape 是一个元组，记录数组每一维分别有多少个元素，如 (行数, 列数)。

生活类比 —— 天气预报里常看到「西北 8 个站点连测 5 天」——矩阵形状就是 (5, 8)。shape 就像一把尺子，量出这块「数字地形」是宽 8 格还是高 5 格。

print(mat.shape)      # (3, 5)  3 行（天）× 5 列（站）
print(mat.size)       # 15，元素总个数 = 3×5

易混淆点 —— reshape 改变形状时元素总个数必须不变（3×5=15，想变成 (5,3) 可以，变成 (4,4) 报错）；另一个坑是 shape 只反映「每个轴有多少格」，不反映「每个格是什么量」，同样的 (3,5) 可能是「3天5站」，也可能是「5天3站」——先看 shape，再看业务含义。

dtype（数据类型）#

dtype 说明数组中每个元素占用内存的类型（整数 int、浮点 float、字节宽度等）。

生活类比 —— 给各站温度统一配的「量杯」大小。用 float32 的杯装着气温，像用小杯子称量温度的小数位；float64 是大杯，精度高、也更占地方。你总不会用一个车站用一个规格的杯子——数组强制统一，气象数据也是如此。

t_f64 = np.array([16.2, 13.5])          # 自动推断 float64
t_f32 = np.array([16.2, 13.5], dtype="float32")   # 手动指定
t_i   = np.array([16, 13], dtype="int32")         # 整数型
print(t_f64.dtype, t_f32.dtype, t_i.dtype)

易混淆点 —— 整型数组做除法可能被强制转成浮点；而用 int 存温度会丢掉小数（16.7 变成 16）。气象温度一定要保证 float，千万别顺手存成 int。

广播（broadcasting）#

当两个数组形状不完全一致时，NumPy 自动把尺寸较小的数组虚拟拉伸成与大的匹配后再逐元素运算，全程不复制真实数据。

生活类比 —— 给一张「3 站 × 5 天」的气温表加一天的订正偏差，等价于要把一根身长 5 格的短木板，拉长去贴住 3 排、每排 5 个钉子——短的这根被自动「复制伸长」成和长木板等长，然后一一对应相加。

mat = np.array([[16.2, 13.5, 14.0, 18.6, 12.8]] * 3)          # 3行5列
bias = np.array([0.5, 0.2, -0.3, 0.1, 0.0])                  # shape (5,)
corrected = mat + bias                                        # (3,5) 与 (5,) 广播
print(corrected.shape)   # (3, 5)

易混淆点 —— 广播必须满足「维度从最右对齐，某维相等或为 1」；否则不是自动扩展，而是报 ValueError（例如把 (3,5) 和 (4,) 相加直接报错）。另外要注意 (3,1) 与 (1,5) 相加会得到 (3,5) 的完整外积式结果，初学者极易看花眼。

向量化（vectorization）#

让「数组整体」直接参与 + - * / ** 等运算、逐元素批量执行，从而取代手工 for 循环的编程方式。

生活类比 —— 不必一箱箱搬到楼上去数，而是一次性把整箱温度计倒进测温仪，同时读出整批数值。气象里把整张温度场同时加 0.5℃，不必每个格点手写一次。

T_k  = np.array([285.0, 288.2, 290.5])   # 3 个格点温度（K）
T_c  = T_k - 273.15                      # 向量化，无需 for 循环
print(T_c)                               # [11.85 15.05 17.35]

易混淆点 —— 数组的 * 是逐元素乘，不是矩阵乘法；矩阵乘法用 @ 或 np.dot()。二者结果完全不同，初学者最容易确定错了方法还找不出 bug。

NaN（非数，缺测标记）#

NaN（Not a Number，非数）是在 float 中表示「缺失 / 无效观测」的特殊值，符合 IEEE 浮点标准，np.nan 常用来代表气象缺测。

生活类比 —— 观测站停电、传感器故障那一天的纪录——不是 0 度、也不是「天气太冷」，而是一个明确写着的空洞「当日无数据」。它是占位符，不是数值本身。

temp = np.array([16.2, np.nan, 14.0, 18.6, 12.8])   # 第 2 个站缺测
print(np.isnan(temp))                    # [False  True False ...]  找缺测
print(np.nanmean(temp))                  # 15.4  自动跳过 NaN 求均值

mu  = np.nanmean(temp)
sd  = np.nanstd(temp)
z   = (temp - mu) / sd                   # 缺测位仍保持 NaN，不污染
print(z)

易混淆点 —— 别用 temp == np.nan 判断缺测——NaN 与任何值（包括它自己）都不相等，必须用 np.isnan()；更别用 fillna(0) 把缺测滥补成 0 度，那会彻底污染均值、标准差与标准化结果，缺测被「填平」后再也找不回来。
