第 8 章术语：气象数据分析（二）Xarray#

配套 气象数据分析（二）Xarray 正文使用。每个词条 = 一句话定义 + 生活类比 + 代码示例 + 易混淆点。阅读前先记住这句话：Xarray 全部魔法都在「标签」二字——同一批数字，贴上维度名、坐标、单位的标签后，就不会再搞混经度经度、日期日期。

参见

配套正文：气象数据分析（二）Xarray

DataArray#

Xarray 中带完整坐标与元信息的多维数据数组，底层封装了 numpy.ndarray 并额外记录维度名、坐标取值、单位等标签。

生活类比 —— 一张带说明书的表格。普通 NumPy 数组就像一张只写着数字的草稿纸——你知道这是温度，但不知道每一行对应哪条纬度、每一列对应哪条经度、单位是 ℃ 还是 K。而 DataArray 这张表格自带说明书：既标了「这是气温」，又标了「单位 ℃、第 0 维是纬向、第 1 维是经向」。取数再也不用「数第几行第几列」，而是直接按「纬度 36°N 上」去抓。

import numpy as np
import xarray as xr

# 一张 3(纬) x 4(经) 的合成气温场（℃），贴上坐标标签
da = xr.DataArray(
    data=np.random.randn(3, 4) + 10,
    dims=["lat", "lon"],
    coords={"lat": [30, 36, 42], "lon": [85, 90, 95, 100]},
    attrs={"units": "degC", "long_name": "temperature"},
)
print(da.sel(lat=36))          # 不要数行，直接按坐标抓某条纬带
print("shape:", da.shape)      # (lat, lon) = (3, 4)

易混淆点 —— DataArray 拥有自己的坐标/维度，但它顶多算「一张表」；一旦同一批坐标要共配多套物理量（温度、气压、湿度），就需要升级成 Dataset。

Dataset#

多个 DataArray 的集合容器，可同时存放若干气象变量，并能共享同一套时间 / 纬度 / 经度坐标。

生活类比 —— 一整本气象档案册。册子里的每一页是一个 DataArray（温度页、气压页、湿度页），但整本册子共用同一份目录——即同一套时间与经纬度坐标。改一次目录页码，所有页都跟着用新坐标，绝不会「温度表用这套纬度、气压表用另一套纬度」。

ds = xr.Dataset(
    {
        "temp": (("lat", "lon"), np.random.rand(3, 4) * 30 - 5),
        "pres": (("lat", "lon"), np.random.rand(3, 4) * 20 + 1000),
    },
    coords={"lat": [30, 36, 42], "lon": [85, 90, 95, 100]},
)
print(list(ds.data_vars))      # ['temp', 'pres']，一个容器装多套物理量
T = ds["temp"]
print(ds["temp"].equals(T))    # True，取出的 DataArray 与容器共享数据

易混淆点 —— Dataset 是容器，DataArray 是变量（单页）。读出时用 ds["temp"]（给变量名），而不是给一个数字下标——变量名才是认领「温度」的钥匙。

维度 dim#

数组每一个轴的名字，例如 time、lat、lon，只描述「数据沿着哪个方向变化」，本身不存任何具体数值。

生活类比 —— 表格的表头分类。就像 Excel 学：第一列叫「时间」、第二列叫「纬度」——表头只说明「这一列是干嘛的」，并不代表具体是 2025-01-01 还是 36°N。dim 就是这份「轴名清单」，da.dims 打印出来通常是 ('time', 'lat', 'lon') 这样的一串名字。

print(da.dims)                 # ('lat', 'lon')，数组有两个轴
print(da.ndim)                 # 2，轴的数量
print(da.sizes)                # {'lat': 3, 'lon': 4}，每个轴有多少个格点

易混淆点 —— dim 是轴的名字，coords 是轴上具体的数值，两者千万别混——「名字」与「内容」是两码事。

坐标 coords#

每个维度对应的实际取值集合，如 lat 维度的坐标是一串 [30, 36, 42] 纬度值，配合标签索引 sel() 按数值取数。

生活类比 —— 档案册的目录页码 + 我在哪。维度只告诉你「按标注定顺序排」；坐标才是具体日期 2025-01-01、具体纬度 36°N。想找「离兰州最近的温度」，直接在坐标里定位到 lat≈36、lon≈104，不用手数这是第几行几列。

print(da.coords)               # lat: (3,) / lon: (4,) 两套坐标
# 按坐标名取值：sel 用的是坐标数值，不是数组序号
sub = da.sel(lat=36, lon=95)
print(sub.values)              # 取出 (lat=36, lon=95) 这一个格点的温度

易混淆点 —— - dim``=轴名字 / ``coords``=轴上的实际数值； - ``sel()（按坐标值取）≠ isel()（按数组序号取）。写 sel(time=0) 会报错，因为坐标里没有「0」这个时间；要取第一个时刻应用 isel(time=0)。

NetCDF#

气象领域事实标准的高度结构化二进制数据格式（后缀 .nc），可同时存多维场、坐标、单位、说明等元数据，Xarray 用 xr.open_dataset 一步读入。

生活类比 —— 专业密封档案盒。一个 .nc 盒子把「数据本身 + 维度 + 坐标 + 单位 + 缺测标识 _FillValue + 来源说明」全部打包封存。不像 .csv 只能装规整的二维表格、还得另开文本文档记说明；NetCDF 天生装得下时间–纬度–经度这种三维四维气象场，靠 _FillValue 语义记录的缺测点（如海洋）也不会和真实数据混在一起。

# 一个 nc 文件内部大致长这样（用 ncdump 或 Python 打开）
# 变量: time(365)  lat(109)  lon(140)
#       float temp(time, lat, lon)
#             temp: units = "K";  _FillValue = -32767.0

# 实际项目第一步
ds = xr.open_dataset("northwest_temp.nc")   # 输出里能看到维度与单位

易混淆点 —— NetCDF 变量名（temp）即钥匙；不同再分析资料（ERA5、NCEP）变量名、单位可能不同，读取后务必核对变量名与 units，别拿来就用。

属性 attrs#

挂在 DataArray / Dataset 上的元信息字典，存储单位、来源、描述等文本说明，不参与任何数值计算。

生活类比 —— 档案盒外面的备注标签。标签上写着「单位：开尔文 K」「数据来源：ERA5 再分析」「实验批次：v2」，这些都只是说明，不会改变里面数字本身——就算把标签撕掉换成「单位：℃」，数字也依然是开尔文，改标签不改数值。同理，代码里 temp.attrs 只读不改数据。

da.attrs["units"] = "degC"              # 改标签，不改数值
da.attrs["source"] = "ERA5 再分析资料"
print(da.attrs)                         # 查看所有元信息
print(da.attrs.get("units", "未知"))    # 'degC'

易混淆点 —— attrs 是描述不是数据；真正要把开尔文转摄氏必须写数值运算 temp - 273.15，单靠改 attrs 温度数字一丝不变。

重采样 resample#

针对时间维度做频率聚合，把高频率数据规约成旬、月、年平均，例如逐时气温 → 日均、日均 → 月均。

生活类比 —— 记账本的月底汇总。你有一堆每天 24 小时的刷卡流水（高频），resample("ME") 把每天归到一个自然月，直接算出每个月总开销与月均支出；气象里就是「把逐小时气温按月求平均，得到月平均温度」。注意它只作用在时间轴上——把一天想归并成月，先要把每天归并理清楚再按月聚。

# 逐小时 30 天温度序列 —— 先按月做日均，再做月平均
hours = xr.cftime_range("2001-01-01", periods=24 * 30, freq="h")
T = xr.DataArray(np.random.randn(24 * 30) + 5, dims="time", coords={"time": hours})
monthly = T.resample(time="ME").mean()     # ME = 月末间隔，得到月度平均序列
print(monthly.shape)                       # 时间点远少于原始逐时点数

易混淆点 —— resample 只聚合时间；空间降维（经纬平均）要用 .weighted(...).mean() 或 .mean(dim=...)，别把两者混为一谈。且在 xarray 新版本里优先用 'ME' 而不是 'M' 表示月末间隔，否则可能触发弃用告警。

备注

维度过 vs 坐标——最值得记的一条

da.dims 告诉你数组有几个轴、分别叫什么；da.coords 告诉你每个轴上每个位置的真实数值。写 sel(lat=slice(40, 30)) 时你动的全是 coords，dim 只是被匹配的轴名字而已。
